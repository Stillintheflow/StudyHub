Overview & Mental Model

React is a UI library for building component-based interfaces. Its core promise: given the same state, your UI always looks the same. React re-renders components when state or props change, and efficiently updates only what changed in the real DOM via a virtual DOM diff.

🧩
Component-Based

UI split into reusable, self-contained pieces. Each component owns its own logic and appearance.

🔄
Declarative

Describe WHAT your UI should look like. React figures out HOW to update the DOM efficiently.

⚡
Reactive State

State changes trigger automatic re-renders. No manual DOM manipulation needed.

🪝
Hooks-First

All logic lives in function components via hooks. Class components are legacy.

The React Mental Model

User Action / Timer / Network │ ▼ ┌─────────────────────┐ │ setState(newVal) │ ← triggers re-render └─────────────────────┘ │ ▼ ┌─────────────────────┐ │ Component Function │ ← called again with new state │ returns JSX │ └─────────────────────┘ │ ▼ ┌─────────────────────┐ │ React Virtual DOM │ ← diffs old vs new JSX tree └─────────────────────┘ │ ▼ ┌─────────────────────┐ │ Real DOM update │ ← only changed nodes updated └─────────────────────┘
Core Rule

Components are just functions: they take props as input and return JSX as output. Keep them pure — same props + state should always produce the same output.

Components & Props

A component is a function that accepts props (an object of inputs) and returns JSX. Component names must start with a capital letter so React can tell them apart from native HTML tags.

Defining Components

// Arrow function component
const Button = ({ label, onClick, variant = 'primary' }) => {
  return (
    <button className={`btn btn-${variant}`} onClick={onClick}>
      {label}
    </button>
  );
};

// Named function component (preferred for debugging)
function UserCard({ name, avatar, bio, children }) {
  return (
    <div className="card">
      <img src={avatar} alt={name} />
      <h2>{name}</h2>
      <p>{bio}</p>
      {children}  {/* slots — whatever the parent puts between tags */}

Props Rules

Props are Read-Only

Never mutate props directly. Props flow down from parent to child (one-way data flow). To communicate back up, pass a callback function as a prop.

// Passing data DOWN via props
<Counter initialCount={0} onFinish={handleFinish} />

// Inside Counter — call the callback to communicate UP
function Counter({ initialCount, onFinish }) {
  const [count, setCount] = useState(initialCount);
  return (
    <button onClick={() => {
      const next = count + 1;
      setCount(next);
      if (next >= 10) onFinish();  // ← child tells parent
    }}>
      Count: {count}
    </button>
  );
}

Prop Patterns

// Spread props
const inputProps = { type: 'email', placeholder: 'Enter email', required: true };
<input {...inputProps} />

// Default values via destructuring
function Tag({ color = 'blue', size = 'md', children }) { ... }

// Rest props forwarding (useful for wrapper components)
function Input({ label, error, ...rest }) {
  return (
    <div>
      <label>{label}</label>
      <input {...rest} />  {/* forward all remaining props */}
      {error && <span className="error">{error}</span>}
    </div>
  );
}

State — useState

State is data that can change over time and cause the component to re-render. useState is the hook for local component state.

import { useState } from 'react';

function Counter() {
  // [currentValue, setterFunction] = useState(initialValue)
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      <button onClick={() => setCount(count - 1)}>−</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

Functional Updates

When the next state depends on the previous state, always use the functional form to avoid stale closure bugs:

// ❌ Bug: can use stale 'count' inside async handlers or event batching
setCount(count + 1);
setCount(count + 1);  // both read the same 'count', result = count + 1 not + 2

// ✅ Correct: callback always gets the latest state
setCount(prev => prev + 1);
setCount(prev => prev + 1);  // result = count + 2

State with Objects & Arrays

Always create new objects/arrays — never mutate

React uses reference equality to detect changes. Mutating in place won't trigger a re-render.

// ── Objects ──
const [user, setUser] = useState({ name: 'Alice', age: 30 });

// ❌ Wrong — mutation, no re-render
user.age = 31;
setUser(user);

// ✅ Correct — new object with spread
setUser(prev => ({ ...prev, age: 31 }));

// ── Arrays ──
const [todos, setTodos] = useState([]);

// Add item
setTodos(prev => [...prev, { id: Date.now(), text: 'New todo' }]);

// Remove item
setTodos(prev => prev.filter(t => t.id !== id));

// Update item
setTodos(prev => prev.map(t => t.id === id ? { ...t, done: true } : t));

Multiple State Variables vs. Object State

// ✅ Multiple variables — easier to update independently
const [name, setName] = useState('');
const [email, setEmail] = useState('');
const [loading, setLoading] = useState(false);

// ✅ Object state — when values are always updated together
const [form, setForm] = useState({ name: '', email: '' });
const updateField = (field, value) =>
  setForm(prev => ({ ...prev, [field]: value }));

useReducer — for complex state logic

import { useReducer } from 'react';

function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    case 'reset':     return { count: 0 };
    default: throw new Error('Unknown action: ' + action.type);
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return (
    <>
      <p>{state.count}</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>−</button>
    </>
  );
}

useEffect

useEffect lets you run side effects after rendering: data fetching, subscriptions, timers, manual DOM manipulation, or anything that reaches outside the component.

Mount
useEffect(() => {}, [])
Update
useEffect(() => {}, [dep])
Unmount
return () => cleanup() 
import { useState, useEffect } from 'react';

// 1. Run EVERY render (no dependency array)
useEffect(() => {
  document.title = `Count: ${count}`;
});

// 2. Run ONCE on mount (empty array)
useEffect(() => {
  fetchUserData();
}, []);

// 3. Run when specific value changes
useEffect(() => {
  fetchPostsByUser(userId);
}, [userId]);  // re-runs whenever userId changes

// 4. Cleanup on unmount (return a function)
useEffect(() => {
  const timer = setInterval(() => setTick(t => t + 1), 1000);
  const sub = socket.subscribe(channel, onMessage);

  return () => {
    clearInterval(timer);  // ← runs before next effect OR on unmount
    sub.unsubscribe();
  };
}, [channel]);

Fetching Data Pattern

function UserProfile({ userId }) {
  const [user, setUser]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    let cancelled = false;  // handle race conditions

    async function load() {
      try {
        setLoading(true);
        setError(null);
        const data = await fetchUser(userId);
        if (!cancelled) setUser(data);
      } catch (err) {
        if (!cancelled) setError(err.message);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }

    load();
    return () => { cancelled = true; };  // cleanup: ignore stale response
  }, [userId]);

  if (loading) return <Spinner />;
  if (error)   return <p>Error: {error}</p>;
  return <div>{user.name}</div>;
}
Tip — prefer data-fetching libraries

In production, use TanStack Query (React Query) or SWR instead of raw useEffect for fetching. They handle caching, deduplication, refetching, and loading states automatically.

useRef

useRef serves two purposes: (1) accessing DOM elements directly, (2) storing mutable values that persist across renders without causing a re-render when changed.

import { useRef, useEffect } from 'react';

// ── 1. DOM access ──
function AutoFocusInput() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus();  // direct DOM access after mount
  }, []);

  return <input ref={inputRef} placeholder="Auto-focused" />;
}

// ── 2. Mutable value (like an instance variable) ──
function StopWatch() {
  const [time, setTime] = useState(0);
  const intervalRef = useRef(null);  // stores the interval ID without re-rendering

  const start = () => {
    intervalRef.current = setInterval(() => setTime(t => t + 1), 1000);
  };
  const stop = () => clearInterval(intervalRef.current);

  return (
    <>
      <p>{time}s</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </>
  );
}

// ── 3. Track previous value ──
function usePrevious(value) {
  const ref = useRef();
  useEffect(() => { ref.current = value; });
  return ref.current;  // value from previous render
}

useContext

Context provides a way to share values across the component tree without passing props through every level (prop drilling).

import { createContext, useContext, useState } from 'react';

// 1. Create the context
const ThemeContext = createContext('light');  // default value

// 2. Provide it at a high level
function App() {
  const [theme, setTheme] = useState('light');

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Layout />
    </ThemeContext.Provider>
  );
}

// 3. Consume it anywhere in the tree — no prop drilling
function ThemeToggle() {
  const { theme, setTheme } = useContext(ThemeContext);

  return (
    <button onClick={() => setTheme(t => t === 'light' ? 'dark' : 'light')}>
      Current: {theme}
    </button>
  );
}
Performance Note

Every component consuming a context re-renders when the context value changes. Split contexts by concern (e.g., separate ThemeContext and AuthContext) so unrelated updates don't cause unnecessary re-renders.

useMemo & useCallback

Both hooks memoize a value so it isn't recalculated on every render. Use them when recalculation is expensive or when referential equality matters (passing callbacks to memoized children).

import { useMemo, useCallback, memo } from 'react';

// useMemo — caches a computed VALUE
function DataTable({ data, filterText }) {
  // Only re-filters when data or filterText changes
  const filtered = useMemo(
    () => data.filter(row => row.name.includes(filterText)),
    [data, filterText]
  );

  return <table>{filtered.map(row => <Row key={row.id} row={row} />)}</table>;
}

// useCallback — caches a FUNCTION reference
function Parent() {
  const [count, setCount] = useState(0);

  // Without useCallback, new function ref on every render → Child re-renders
  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []);  // stable reference — no deps

  return (
    <>
      <button onClick={() => setCount(c => c + 1)}>+</button>
      <MemoizedChild onClick={handleClick} />  {/* won't re-render */}
    </>
  );
}

// memo — skips re-render if props haven't changed
const MemoizedChild = memo(function Child({ onClick }) {
  console.log('Child rendered');
  return <button onClick={onClick}>Click me</button>;
});
When to use
  • useMemo — expensive computations (sorting/filtering large lists, complex calculations)
  • useCallback — when passing callbacks to memo-wrapped children
  • Don't add either by default — they add overhead; profile first

Custom Hooks

Custom hooks are plain functions that start with use and call other hooks. They let you extract and reuse stateful logic between components.

// useLocalStorage — persist state in localStorage
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const stored = localStorage.getItem(key);
      return stored ? JSON.parse(stored) : initialValue;
    } catch { return initialValue; }
  });

  const set = useCallback((val) => {
    const toStore = typeof val === 'function' ? val(value) : val;
    setValue(toStore);
    localStorage.setItem(key, JSON.stringify(toStore));
  }, [key, value]);

  return [value, set];
}

// useDebounce — delay a value update
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debounced;
}

// useFetch — simple data fetching
function useFetch(url) {
  const [data, setData]     = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]   = useState(null);

  useEffect(() => {
    let cancelled = false;
    fetch(url)
      .then(r => r.json())
      .then(d => { if (!cancelled) { setData(d); setLoading(false); } })
      .catch(e => { if (!cancelled) { setError(e); setLoading(false); } });
    return () => { cancelled = true; };
  }, [url]);

  return { data, loading, error };
}

// ── Usage ──
function SearchBox() {
  const [query, setQuery] = useLocalStorage('search', '');
  const debouncedQuery    = useDebounce(query, 400);
  const { data, loading } = useFetch(`/api/search?q=${debouncedQuery}`);

  return (
    <>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      {loading ? <Spinner /> : <Results data={data} />}
    </>
  );
}

Conditional Rendering

function Alert({ type, message, onClose }) {
  // 1. Return early (guard clause)
  if (!message) return null;

  // 2. Ternary for either/or
  const icon = type === 'error' ? '❌' : '✅';

  return (
    <div className={`alert alert-${type}`}>
      {/* 3. Short-circuit for optional element */}
      {onClose && <button onClick={onClose}>✕</button>}

      {/* 4. IIFE for complex logic inline */}
      {(() => {
        if (type === 'error') return <strong>Error: </strong>;
        if (type === 'warn')  return <strong>Warning: </strong>;
        return null;
      })()}

      {icon} {message}
    </div>
  );
}
0 is Falsy in JSX!

{count && <Badge />} renders 0 when count is 0, not nothing. Use {count > 0 && <Badge />} or {!!count && <Badge />} to be safe.

Lists & Keys

Keys help React identify which items changed, were added, or removed. They must be unique among siblings and stable (don't use array index if the list can reorder).

function TodoList({ todos }) {
  return (
    <ul>
      {todos.map(todo => (
        <TodoItem
          key={todo.id}      {/* ← unique, stable ID */}
          todo={todo}
        />
      ))}
    </ul>
  );
}

// ❌ Index as key — breaks when items reorder or are inserted
{items.map((item, index) => <Item key={index} />)}

// ✅ Use a stable, unique ID from your data
{items.map(item => <Item key={item.id} />)}

Forms

Controlled Components (recommended)

React controls the input value via state. The input is always in sync with state.

function LoginForm() {
  const [form, setForm] = useState({ email: '', password: '' });
  const [errors, setErrors] = useState({});

  const handleChange = (e) => {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = async (e) => {
    e.preventDefault();
    // validate
    const newErrors = {};
    if (!form.email.includes('@')) newErrors.email = 'Invalid email';
    if (form.password.length < 8)  newErrors.password = 'Min 8 chars';
    if (Object.keys(newErrors).length) { setErrors(newErrors); return; }

    await login(form);
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <input
          name="email"
          value={form.email}
          onChange={handleChange}
          type="email"
        />
        {errors.email && <span>{errors.email}</span>}
      </div>
      <div>
        <input
          name="password"
          value={form.password}
          onChange={handleChange}
          type="password"
        />
        {errors.password && <span>{errors.password}</span>}
      </div>
      <button type="submit">Login</button>
    </form>
  );
}

Lifting State Up

When two sibling components need to share state, lift state up to their closest common ancestor and pass it down via props.

// ── Before: each has its own state, they can't sync ──
function TempCelsius()    { const [val, setVal] = useState(0); ... }
function TempFahrenheit() { const [val, setVal] = useState(32); ... }

// ── After: state lifted to parent ──
function TemperatureConverter() {
  const [celsius, setCelsius] = useState(0);

  const fahrenheit = celsius * 9/5 + 32;
  const handleCelsiusChange    = (c) => setCelsius(c);
  const handleFahrenheitChange = (f) => setCelsius((f - 32) * 5/9);

  return (
    <>
      <TempInput
        label="Celsius"
        value={celsius}
        onChange={handleCelsiusChange}
      />
      <TempInput
        label="Fahrenheit"
        value={fahrenheit}
        onChange={handleFahrenheitChange}
      />
    </>
  );
}

function TempInput({ label, value, onChange }) {
  return (
    <label>
      {label}: <input
        type="number"
        value={value}
        onChange={e => onChange(Number(e.target.value))}
      />
    </label>
  );
}

// Component passes data back to parent through a render function prop
function MouseTracker({ render }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });

Compound Components

// Parent + child components share implicit state via context
const TabsContext = createContext();

function Tabs({ children, defaultTab }) {
  const [active, setActive] = useState(defaultTab);
  return (
    <TabsContext.Provider value={{ active, setActive }}>
      <div className="tabs">{children}</div>
    </TabsContext.Provider>
  );
}

Tabs.List = function TabList({ children }) {
  return <div className="tab-list">{children}</div>;
};

Tabs.Tab = function Tab({ id, children }) {
  const { active, setActive } = useContext(TabsContext);
  return (
    <button
      className={active === id ? 'active' : ''}
      onClick={() => setActive(id)}>
      {children}
    </button>
  );
};

Tabs.Panel = function Panel({ id, children }) {
  const { active } = useContext(TabsContext);
  return active === id ? <div>{children}</div> : null;
};

// Usage — clean, semantic, no prop drilling
<Tabs defaultTab="home">

Context API Pattern

The recommended pattern: encapsulate context creation, provider, and hook in one module.

// auth-context.jsx
import { createContext, useContext, useState } from 'react';

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  const login  = async (creds) => { const u = await api.login(creds); setUser(u); };
  const logout = ()            => { api.logout(); setUser(null); };

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom hook — throws if used outside provider (catches mistakes early)
export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be used inside <AuthProvider>');
  return ctx;
}

// app.jsx — wrap at the top
function App() {
  return (
    <AuthProvider>
      <Router>
        <Routes />
      </Router>
    </AuthProvider>
  );
}

// Anywhere in the tree
function Header() {
  const { user, logout } = useAuth();
  return user ? <button onClick={logout}>Logout {user.name}</button> : <Login />;
}

const Dashboard = lazy(() => import('./Dashboard'));

function App() {
  return (

      <Routes>
        <Route path="/dashboard" element={<Dashboard />} />
        <Route path="/reports"   element={<Reports />} />
      </Routes>
    </Suspense>
  );
}

Error Boundaries

Error Boundaries catch JavaScript errors in their child component tree and display a fallback UI. They must be class components (no hook equivalent yet).

import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    // Log to error tracking service
    logErrorToService(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || <h2>Something went wrong.</h2>;
    }
    return this.props.children;
  }
}

// Usage — wrap risky subtrees
<ErrorBoundary fallback={<p>Chart unavailable</p>}>
  <ComplexChart data={bigData} />
</ErrorBoundary>

Suspense & Lazy

Suspense lets components "wait" for something before rendering and show a fallback meanwhile. Combined with lazy() for code splitting, or data libraries (TanStack Query, Relay) for data.

// Suspense + lazy (code splitting)
const HeavyMap = lazy(() => import('./HeavyMap'));

function Page() {
  return (
    <Suspense fallback={<MapSkeleton />}>
      <HeavyMap />
    </Suspense>
  );
}

// Multiple concurrent data fetches with React 18 + TanStack Query
function Dashboard() {
  return (
    <Suspense fallback={<Skeleton />}>
      <ErrorBoundary fallback={<Error />}>
        <UserStats />    {/* these fetch in parallel */}
        <RecentOrders />
      </ErrorBoundary>
    </Suspense>
  );
}

Portals & forwardRef

Portals

Portals render children into a DOM node outside the parent component's DOM hierarchy — perfect for modals, tooltips, and toasts.

import { createPortal } from 'react-dom';

function Modal({ isOpen, onClose, children }) {
  if (!isOpen) return null;

  // Renders into document.body, not inside the component's DOM parent
  return createPortal(
    <div className="modal-overlay" onClick={onClose}>
      <div className="modal" onClick={e => e.stopPropagation()}>
        {children}
        <button onClick={onClose}>Close</button>
      </div>
    </div>,
    document.body
  );
}

forwardRef

Allows a parent to access a ref of a DOM element inside a child component.

import { forwardRef } from 'react';

// Child exposes its internal input ref
const FancyInput = forwardRef(function FancyInput(props, ref) {
  return <input ref={ref} className="fancy" {...props} />;
});

// Parent can now focus the input inside FancyInput
function Form() {
  const inputRef = useRef();

  return (
    <>
      <FancyInput ref={inputRef} placeholder="Name" />
      <button onClick={() => inputRef.current.focus()}>Focus</button>
    </>
  );
}

Zustand — minimal example

import { create } from 'zustand';

const useStore = create((set) => ({
  count: 0,
  user: null,
  increment: () => set(state => ({ count: state.count + 1 })),
  setUser:   (user) => set({ user }),
  reset:     () => set({ count: 0 }),
}));

// Use it anywhere — no Provider needed
function Counter() {
  const { count, increment } = useStore();
  return <button onClick={increment}>{count}</button>;
}

Redux Toolkit — slice pattern

import { createSlice, configureStore } from '@reduxjs/toolkit';
import { Provider, useSelector, useDispatch } from 'react-redux';

// Slice = reducer + actions in one
const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: state => { state.value += 1; },  // Immer under the hood — mutation OK here
    decrement: state => { state.value -= 1; },
    setAmount: (state, action) => { state.value = action.payload; },
  },
});

export const { increment, decrement, setAmount } = counterSlice.actions;

const store = configureStore({ reducer: { counter: counterSlice.reducer } });

// Wrap app
<Provider store={store}><App /></Provider>

// In component
function Counter() {
  const count    = useSelector(state => state.counter.value);
  const dispatch = useDispatch();
  return <button onClick={() => dispatch(increment())}>{count}</button>;
}

Rules & Best Practices

Rules of Hooks

These rules are enforced by the eslint-plugin-react-hooks linter
  • Only call hooks at the top level of a component or custom hook — never inside loops, conditions, or nested functions
  • Only call hooks from React function components or custom hooks — not from regular JS functions
Wrong 
function Bad({ flag }) {
  if (flag) {
    // ❌ conditional hook
    const [x] = useState(0);
  }
  for (let i = 0; i < 3; i++) {
    // ❌ hook in loop
    useEffect(() => {}, []);
  }
}
Correct 
function Good({ flag }) {
  // ✅ always at top level
  const [x] = useState(0);

  useEffect(() => {
    // put conditional inside
    if (flag) doSomething();
  }, [flag]);
}

Key Principles

PrincipleWhy it matters
Keep components small and focusedEasier to test, reuse, and reason about
Derive state, don't duplicate itAvoids sync bugs — compute from existing state instead of storing redundant state
State as low as possibleMinimizes re-render scope; only lift when truly needed by siblings
Effects are for synchronizationuseEffect syncs React state with external systems — not for data transformations
Avoid deeply nested stateUse flat structures; normalization makes updates simpler
Co-locate state with consumersPut state in the component that uses it, not always at the top

Common Anti-Patterns

// ❌ Mirroring props in state (derived state antipattern)
function UserName({ name }) {
  const [localName, setLocalName] = useState(name);  // won't update if 'name' prop changes!
  return <span>{localName}</span>;
}
// ✅ Just use the prop directly, or if you need it editable: use a key to reset
<UserName key={userId} name={user.name} />

// ❌ Infinite loop — effect updates a value it also depends on
useEffect(() => {
  setCount(count + 1);  // count in deps → infinite loop!
}, [count]);

// ✅ Use functional update — no dependency on count needed
useEffect(() => {
  setCount(prev => prev + 1);
}, []);  // runs once

// ❌ Creating objects/arrays in render as prop values (breaks memo)
<Child config={{ color: 'red' }} />  // new object every render!
// ✅ Define outside or memoize
const config = useMemo(() => ({ color: 'red' }), []);
<Child config={config} />

All Core Hooks at a Glance

useState

Local component state. Returns [value, setter]. Setter triggers re-render.

useReducer

Complex state with multiple sub-values or next state depends on previous. Pairs with dispatch.

useEffect

Side effects: fetch, timers, subscriptions. Runs after render. Return cleanup function.

useLayoutEffect

Like useEffect but fires synchronously after DOM mutations. Use for measuring layout.

useRef

Mutable container (.current) that persists without re-rendering. DOM access or instance vars.

useContext

Read context value from nearest Provider above. Component re-renders on context change.

useMemo

Cache expensive computed value. Re-computes only when deps change.

useCallback

Cache function reference. Prevents re-creating callbacks on every render.

useId

Generate stable unique IDs for accessibility (aria-labelledby etc). React 18+.

useTransition

Mark state update as non-urgent. UI stays responsive during expensive re-renders. React 18+.

useDeferredValue

Defer re-rendering a less important part of the UI. Like debounce but integrated with React. React 18+.

useImperativeHandle

Customize the ref value exposed to parent when using forwardRef. Use sparingly.
